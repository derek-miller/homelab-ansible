# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Ansible-managed homelab. Docker Swarm (rackvm1-3 managers, rackvm4-5 workers, amd64 VMs on the pve1-5 Proxmox cluster) runs the user-facing services; a Mac mini (`rackmini1`) runs native-only services outside the swarm (Plex, Homebridge, Tailscale, SMB mounts). One playbook, `playbooks/default.yml`, organised as sequential plays selected by tag.

## Read this before editing anything

- **Service config lives in Ansible Vault, not in the tree you can grep.** The entire Docker Swarm stack (services, volumes, networks) is the `vault_docker_stack_definition` variable inside `playbooks/host_vars/rackvm1/vault.yml`, and per-host Compose stacks are `docker_compose_definition` in each host's `vault.yml`. Deployed config files live under `playbooks/files/vault/{hostname}/...`. A plain grep reads these as opaque AES blobs and reports them absent — decrypt (`make vault-decrypt`) before concluding anything is undeclared.
- **Run `make vault-encrypt` before committing.** `hooks/pre-commit` runs `make vault-check` and rejects the commit otherwise. The Makefile hard-errors unless `VIRTUAL_ENV` is set, so commit from inside `.venv`.
- **The pve1-5 plays are opt-in, and that is what keeps them out of CI.** They are in `default.yml` alongside the swarm plays, but their host patterns resolve to nothing unless a run passes `-e proxmox_enabled=yes`. The `Deploy` workflow runs plain `make run`, so a push to master never touches a hypervisor. The flag has to be an extra var: Ansible resolves a play's `hosts:` before `group_vars` load. The shared plays exclude the group the other way round, with `all:!proxmox`, because `ansible/setup/connection` forces become-to-root and PVE has no sudo.
- **The swarm stack is named `rackpis` and every volume is `rackpis_*`.** The rackpi hosts are long gone; the name is not. Renaming the stack points all 41 services at empty volumes, so it stays regardless of which hosts run it.

## Commands

```bash
make after-git-pull     # Install all deps after pulling
make run                # Default playbook, all hosts
make run hosts=rackvm1  # Limit to a host
make run tags=docker    # Limit to a tag (implies --skip-tags=base,common)
make dry-run            # --check
make check              # Syntax validation
make bootstrap hosts=<host> user=<user>

# The proxmox plays sit in the same playbook but select no hosts unless
# proxmox_enabled is set, which only these targets do. hosts=/tags= work here too.
make bootstrap-proxmox user=root   # First contact: asks for the PAM password, authorises
                                   # the repo key for root, then forms or joins the cluster
make run-proxmox hosts=pve3 tags=proxmox-cluster
make dry-run-proxmox

# Vault
make vault-diff         # Vault changes (use for commit messages)
make vault-encrypt      # Required before commit
make vault-decrypt      # Decrypt for editing
make vault-check        # Verify encryption (pre-commit hook)

# Dependencies
make -B requirements.txt              # Recompile Python deps
make -B requirements.txt UPGRADE=1    # Upgrade unpinned packages
make galaxy-install                   # Reinstall Galaxy roles/collections
```

## Conventions

- Inventory groups in `playbooks/hosts` are by **function** (`docker`, `docker_swarm_manager`, `raspberry-pi`, `cifs-shares`, ...), not by machine, and carry inline vars. Plays in `default.yml` select on them by tag.
- `playbooks/roles/galaxy/` is gitignored and generated by `make galaxy-install` from `roles/requirements.yml`, so it is absent from a fresh clone. The checked-in roles are `ansible/` (connection/bootstrap), `common/`, and `generic/`.

- **Placement is by node label, never by hostname.** Services pin with `node.labels.<name> == true`. Each label is declared on exactly one host as a comma-delimited `docker_labels` in the `[docker_labels]` inventory group, and `default.yml` reconciles those onto the nodes. `portainer-agent` is `mode: global`; nothing else pins to a host.
- **A role that installs something splits `present.yml` / `absent.yml`,** routed from `tasks/main.yml` on a `<role>_state` variable. `absent` must fully reverse `present`: stop the service, remove config, uninstall the package, clear the repo and keyring.
- Vault variables are referenced indirectly: `docker_stack_definition: "{{ vault_docker_stack_definition }}"`. Layering is role defaults → group_vars → host_vars.
- The `project-files` role deploys from `playbooks/files/plaintext/{hostname}/` and `playbooks/files/vault/{hostname}/` to target paths, keyed by hostname.
- Traefik labels on swarm services carry routing, OAuth middleware, and TLS.
